# mnemo v1.1.0 — release notes

## Highlights

- Add `mnemo track [--path=DIR]` for explicit, opt-in Git tracking of the project's `.mnemo` marker. The command removes the old direct `.mnemo` exclusion from the repository's `.gitignore` and stages the marker when it is not already tracked.
- Preserve the existing project ID across Git clones once the marker has been committed. `mnemo track` never changes the project's UUID, creates commits or pushes changes.
- `mnemo init` no longer adds `.mnemo` to `.gitignore`, nor does it automatically stage files. Git tracking remains a separate decision.
- `mnemo migrate` preserves existing project IDs rather than replacing them with a UUID derived from the local path. Legacy projects with no ID still receive one during migration.
- Improve Git migration safety: a failed tracking attempt restores the repository's previous `.gitignore` content. Add tests covering idempotency, external ignore rules, Git errors and project identity preservation.

## Important change for existing installations

**After updating mnemo, run `mnemo track` in each Git repository where you want to version the existing `.mnemo` file.** This is recommended for users who want one project identifier across machines, but it is not mandatory. Updating the binary does not modify existing repositories, and rerunning `mnemo init` does not start tracking.

From inside a previously initialized Git repository:

```bash
mnemo update
mnemo track
git status
```

The `mnemo track` command stages only `.mnemo`. The updated `.gitignore` remains an ordinary working-tree change: review and stage it separately before committing the migration. No commit or push is performed by mnemo.

**Privacy and authorization:** `.mnemo` currently contains the project identifier and enabled agent names, not the SQLite memories or credentials. Publishing the marker shares its identifier, **not** authorization to access memories. Any future cloud synchronization must enforce user/project authorization on every request (OWASP API1:2023, Broken Object Level Authorization).

## Installation and distribution

The latest stable release is installed through the official installer:

```bash
curl -sSf https://raw.githubusercontent.com/jmeiracorbal/mnemo/main/install.sh | bash
mnemo version
mnemo doctor --agent=all --path=.
```

The installer and `mnemo setup refresh` remain the single source of truth for agent setup: MCP registration, hooks, global instructions and skills. Claude Code and Codex marketplace plugins from older versions are **not** distributed or updated; separate plugin registration was retired to avoid duplicate MCP servers. Existing legacy registrations are diagnosed by `mnemo doctor` and may be repaired with `mnemo doctor --fix`.

## Release verification

- GitHub Actions CI must pass on the tagged `main` commit, including Linux/macOS tests, Linux race tests, lint and vulnerability checks.
- Release assets must include macOS/Linux binaries for amd64/arm64 (as supported by the release workflow), SHA-256 checksums, and the scripts archive and checksum.
- After publication, verify the official installer in an isolated `HOME` and `MNEMO_INSTALL_DIR`, `mnemo version` reporting `v1.1.0`, project initialization, `mnemo doctor`, and the `mnemo track` Git behavior.
- Only after the new artifacts exist, update the pinned `v1.0.1` examples in `install.sh` and the English, Spanish and Chinese READMEs to `v1.1.0`.

# mnemo v2.1.0 — private project markers and canonical project IDs

Mnemo 2.1 makes project identity local by default and clarifies how callers identify a project when using the MCP tools.

## Project markers stay local

- `mnemo init` adds `/.mnemo` to the project's `.gitignore` and refuses to initialize a marker that is already tracked. Existing project IDs are preserved; new projects receive a random UUID v4.
- Remove an already tracked marker from the Git index with `git rm --cached -- .mnemo`. The local file remains in place, and the ignore rule prevents it from being committed again.
- Remove `mnemo track`. Project identity is no longer shared by committing `.mnemo`; future sharing will be handled through explicit cloud registration and authorization.

The marker contains a project identifier and enabled agent names. The identifier is not an authorization credential.

## Canonical project IDs in MCP

Clarify that MCP memory operations require the canonical project ID from `.mnemo`, rather than a human-readable project name. This avoids mismatches when callers use labels such as `platform` in place of the marker's UUID.

## Go module and downloads

The Go module remains `github.com/jmeiracorbal/mnemo/v2`; the public client and protocol imports remain under that path.

The release includes binaries and SHA-256 checksums for macOS and Linux on amd64 and arm64, plus the scripts archive and its checksum.

# mnemo v1.0.0 — release notes

## Highlights

- One installation-wide event controller owns persistence and session state.
  Agent event publishers communicate with the controller rather than opening
  the SQLite database directly.
- Durable event delivery and idempotent command handling.
- Project-scoped activation through `.mnemo`, with a canonical project ID.
- Shared memory behavior through MCP, hooks, and skills for Claude Code,
  Codex, Cursor, OpenCode, and Pi.
- Centralized installer-managed integrations and `mnemo doctor` diagnostics.
- Local SQLite + FTS5 storage, schema migrations, memory curation, and
  project merge/rename tooling.
- Separate `mnemo-adapters` and `mnemo-events` modules for integration and
  event contracts.
- Release jobs now require the reusable CI suite to pass, including macOS and
  Linux builds/tests, Linux race testing, linting, and vulnerability scanning.
- Build with Go 1.26.10, including its `crypto/x509` security fix.

## Breaking changes since v0.39.0

- Event persistence uses a singleton per-user controller. Integrations must
  use the v1 event and command interfaces rather than assuming direct access
  to the store.
- Global agent setup is managed by `mnemo setup refresh` and the installer,
  not by separate mnemo agent plugins. Existing legacy plugin registrations
  should be inspected with `mnemo doctor` and repaired using
  `mnemo doctor --fix` only after reviewing its proposed changes.
- Hook event delivery and MCP session ownership follow the current
  controller-managed lifecycle. Downstream integrations using historical
  hooks or session semantics may need to adapt.

For users upgrading directly from a `v1.0.0-beta.5` installation, keep
existing data and controller configuration intact until the installed
`v1.0.0` binary has been verified.

## Installation and upgrade

The stable installer resolves the latest published stable release by default:

```bash
curl -sSf https://raw.githubusercontent.com/jmeiracorbal/mnemo/main/install.sh | bash
mnemo version
mnemo doctor --agent=all --path=.
mnemo db migrate --check --json
```

On an existing installation, inspect the current version and controller state
before any manual database migration. `mnemo db migrate` is an offline
maintenance command: stop the controller before applying migrations.
The installer and `mnemo update` manage agent configuration.

## Release verification

- All GitHub Actions checks pass on the tagged commit.
- macOS and Linux binaries and their SHA-256 checksums are attached.
- The scripts archive and its SHA-256 checksum are attached.
- A remote installation under an isolated `HOME` and
  `MNEMO_INSTALL_DIR` succeeds.
- `mnemo version` reports `v1.0.0`; the MCP server advertises the same
  version.
- Fresh project activation, `mnemo doctor`, and one complete memory
  write/search path succeed.
- Repeated setup and migration checks do not introduce duplicates or errors.

The release workflow verifies the tagged commit before uploading assets. Verify
installation and version metadata against the published release artifacts.
